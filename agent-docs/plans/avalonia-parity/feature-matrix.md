### Observations for D1

- **Natural seam:** `ICommandService` is already the right shape for a Core `IEditorModel` (project, selection, viewport, add/delete/copy/paste/zoom, change events). Its dependencies are only Core types, `Newtonsoft.Json` and `Project`/`Settings` statics, so `CommandService` can move to `Trizbort.Core` almost unchanged. Rename the `Invalidate`-style events to model-changed events and drop `_internalClipboard` in favour of an injected `IClipboard`.
- **Selection first:** fix the selection type before moving anything else. Use an ordered list with a distinct primary item (legacy `_selectedElements` semantics) instead of the `HashSet` plus `Project.ActiveSelectedElement`. Swap, Join and the navigation commands all depend on order (X010, X027).
- **Hit-testing needs no text measurement:** `Element.Distance` / `Intersects` in Core use bounds (`Room.Distance` calls `UnionBoundsWith`), so X034-X036 move as pure functions of world position plus snap distance. The thing to check is whether `UnionBoundsWith(includeMargins: true)` for labels or connections ever calls a text-size routine. If it does, a Core `ITextMeasurer` is needed; if not, hit-testing is free of UI types.
- **Gesture state machine can move nearly as is:** `CanvasDragMode`, the pending-connection logic, `EndDrag(cancelled)` and `IsDegenerateConnection` (X037-X043) only touch Core types plus `KeyModifiers`, `Pointer.Capture` and `Cursor`. Define a neutral `PointerInput` (button, modifiers, client and world position, click count) and a `CursorKind` enum, and put it in a Core `CanvasInteraction`. Avalonia's cancel/restore behaviour is better than legacy's and is the one to keep.
- **Behavioural differences to settle during the move, not after:** press priority (waypoint vs handle vs port), button mapping (right-drag pan vs right-click menu), Shift/Ctrl selection semantics, ZOrder-aware hit-testing, waypoint drag threshold, wheel invert and micro zoom. Core tests written against legacy behaviour (with Avalonia's gesture cancel on top) would pin these.
- **Reuse, don't rewrite:** `CopyController` (including its static clipboard handlers), `RoomController`, `MapEditing`, `CanvasTransform` and the Room/Connection helpers (`Reverse`, `RotateConnector`, `AdjustAllRoomConnections`, `DeleteAllRoomConnections`, `GetConnections(compass)`, `AreRoomsConnected`, `Backup`) are already in Core. Roughly 25 of the 53 rows are one-line orchestration over those helpers (X005-X009, X016, X024-X029, X032, X033).
- **Missing editing commands are cheap to add in Core:** select-special (X008), swap (X027), z-order (X007), start/end room and validation (X029), lighting and shape (X028) are each S and are the backing for ~45 M/K/C rows. A `CommandRegistry` with `CanExecute`/`IsChecked` (X050) lets the main menu, toolbar, context menu and key table share them.
- **Key dispatch:** `Keys`/`ModifierKeys`/`KeyEventArgs` (X020, X051) must become a Core `KeyGesture` type. Core already has a `ModifierKeys` enum (`Domain/Enums/ModifierKeys.cs`), so reuse it for the gesture and write a thin Avalonia `Key` mapper.
- **Dialogs and message boxes:** `ShowElementProperties`, `newRoom.ShowDialog()`, `QuickFind`, `UserInteraction.ShowMessage` (X018, X026, X031, X033) need an `IUserInteraction`/`IDialogService` in Core. Commands should ask the interface and return, not block. A command that needs a dialog (Add-or-connect creating a room) should be split into "model change" and "request edit of element".
- **Undo — mutation funnel:** nothing in either UI goes through a single mutation path. Avalonia sets `IsDirty` at ~12 sites, resizes with direct `Size =` assignments (X022), moves with `MapEditing.Move` during pointer move and edits ports during drags. Commands in X004-X029 mutate element properties directly. Plan for (a) a command layer for discrete edits (most rows), and (b) a gesture-scoped transaction for drags (begin on press, one undo entry on `EndDrag(!cancelled)`, discard on cancel). Avalonia's cancel/restore code in X042 already carries the "before" snapshot (`_dragMovePortOriginalPort/Position`) that (b) needs.
- **Undo — things that break simple property-diff commands:** paste and add-room-with-insert create several elements with interlinked ids (`OldId`, `ReferenceRoomId`, ports by `PortId`) (X012, X015); delete of a room must restore its removed connections (X014, X026); `Room.Id` / `Connection` ids are allocated by element constructors. Snapshot/restore through the existing JSON `CopyController` object may be the cheapest uniform undo for these.
- **Automap:** `AvaloniaAutomapCanvas` marshals automap calls onto the UI thread through `Dispatcher`. If the editor model is in Core, automap should call the model directly, with one undo step per run (or excluded), not go via a UI dispatcher.
- **Rendering-side duplicates to leave in the UI:** `SpatialLineIndex`, `_spatialVersion`, `RecomputeSmartLineSegments`, `DrawGrid`, `RenderToBitmap` (MCC:1576+). They should read model state and subscribe to a model-changed event, nothing more.
